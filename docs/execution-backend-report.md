# Execution backend report

`agentrelay/execution.py` adds explicit worker execution through `ExecutionManager(store, config_path=None)`. A trusted JSON file supplies fixed argv commands, a working directory, declared model and effort, allowed profiles and timeout. Tickets and HTTP actions cannot provide commands. With no config, execution is disabled and manager construction does not recover or launch runs.

An enabled manager holds an OS file lock beside the SQLite database. The `execution_runs` table also has a unique active-run index. Starting a run checks profile compatibility and nonempty acceptance criteria, then claims the ticket and inserts the run in one `BEGIN IMMEDIATE` transaction. The worker receives a single UTF-8 JSON object on stdin. Its stdout must be one JSON result up to 1 MiB. `submit` moves the ticket to review; `help`, `split` and `blocked` record a checkpoint and leave it blocked. The manager never completes or approves a ticket.

Each result is applied only when the ticket still has the exact claim revision, `in_progress` status and run assignee. External edits make the run `conflict` without overwriting the ticket. Failure, timeout and cancellation block an unchanged owned ticket with a bounded reason. A newly enabled manager marks stale `running` rows `interrupted` and blocks unchanged owned tickets; it never retries automatically. Windows cancellation uses `taskkill /PID <owned child PID> /T /F`; POSIX uses the worker's own process group. Worker windows stay hidden on Windows. Local stdout/stderr diagnostics are retained in `Path(db).parent/runs/<run_id>/`, capped at 1 MiB per file and excluded from snapshots and exports.

Validation: `D:\AgentWorkspace\agentrelay\.runtime\Scripts\python.exe -m unittest tests.test_execution -v` passed all eight fixture subprocess tests before the final UTF-8 and diagnostic hardening. The two directly affected tests passed afterward with `python -m unittest tests.test_execution.ExecutionTests.test_submit_records_run_without_auto_review tests.test_execution.ExecutionTests.test_blocked_failure_timeout_and_invalid_output -v`. The suite covers submit without auto-review, help/split, explicit block, invalid JSON, nonzero exit, oversized output, timeout, cancellation, contention, stale revisions, restart recovery, acceptance and profile checks. The fixtures are local Python scripts, not model calls.

Known limits: configured model and effort are declarations by the local operator, not attestation from a provider. Evidence references require independent review. Diagnostic files contain raw worker output and should remain in the ignored local data directory. Normal `close()`, cancellation and handled exceptions terminate the owned process tree. An abrupt host crash can leave an orphan worker or descendant on Windows or POSIX: the new manager marks the run interrupted and blocks the ticket, but it cannot prove the orphan stopped. Recovery deliberately does not kill a persisted PID because that PID may have been reused by an unrelated process. Operators should inspect local processes and files before retrying interrupted work; adapters should not detach independent daemons.

## Adapter artifact directory

Diagnosis: the Codex and Ollama bridges previously placed `schema.json`, `response.json`, `report.md` and `receipt.json` under `<cwd>/.agentrelay/artifacts/<run-uuid>`. For an audit whose `cwd` is an active project, this created adapter artifacts inside that project even when the ticket only called for reading it.

Both adapter CLI subcommands now accept `--artifacts-dir BASE`. An absolute base is used as given; a relative base is resolved from the adapter process `cwd`. Each invocation creates a new UUID child, so a fixed worker configuration can process multiple tickets without overwriting prior reports. The existing default base remains `<cwd>/.agentrelay/artifacts`. The receipt records absolute `cwd` and `artifacts_dir` paths. The provider continues running with the same `cwd`, model and sandbox settings.

Validation: `D:\AgentWorkspace\agentrelay\.runtime\Scripts\python.exe -m unittest tests.test_adapter_artifacts -v` passed all four tests with `TEMP` and `TMP` pointed at a writable C: temporary root. This sandbox's default Windows temporary root denied nested writes during test setup; the tests now use `TemporaryDirectory(prefix='agentrelay-adapter-')` and no longer use the repository's `.runtime` directory. A simulated Codex CLI run used an absolute external base and verified the unchanged project directory and `read-only` sandbox argument. The Ollama CLI path used a fixed provider response to verify relative resolution, two distinct run directories and the unchanged project. Tests also confirmed the legacy default and rejection of an artifact base that is a file. The test environment blocked a loopback HTTP fixture, so the Ollama provider call was replaced in-process; no live model or external network was used.

Limit: this moves files managed by the adapter. A worker given `workspace-write` or other write-capable tools can still edit its project through those tools; `--artifacts-dir` does not change that authority. For a read-only audit, keep the existing `read-only` sandbox setting and point `--artifacts-dir` outside the project.

## Verified text snapshot input

Both adapter subcommands now accept `--input-snapshot DIR`. Before creating artifacts or contacting a provider, the adapter calls `verify_snapshot(DIR)`, reads only its copied manifest and `files/` contents, checks size and SHA-256 again, decodes strict UTF-8, rejects binary control characters, and verifies the snapshot once more. It adds `context.input_snapshot` with `snapshot_id`, `captured_at`, `source_root` as metadata, and each file's `path`, `sha256`, `size`, and exact `text`. It never reads `source_root`. An enriched context above 512 KiB serialized as UTF-8 fails; the snapshot module's separate 8 MiB capture ceiling remains unchanged. The original worker packet is deep-copied and left intact.

Only when that explicit verification succeeds does the provider receive a system note saying the host verified the supplied hashes and the text is untrusted source data. The note does not claim that the agent recalculated hashes. The receipt gains `snapshot_id` and the SHA-256 of the exact manifest bytes. Runs without the flag retain their previous packet and receipt shape. Models, sandbox settings and provider choices are unchanged.

Five fixture tests in `tests/test_adapter_context.py` passed without contacting a model: exact Spanish UTF-8 content for both adapter CLI routes, deep-copy preservation, receipt provenance, source deletion after capture, and rejection of corrupt, binary, control-character, oversized and missing snapshots before provider calls. Windows sandboxed Python denied `Path.resolve(strict=True)` even on local test directories; the full five-case run used one automatically approved unsandboxed test command. After tightening the system note to depend on explicit verification rather than an untrusted context key, the two affected no-snapshot/error tests and `py_compile` passed in the sandbox. The coordinator will run final integrated validation.

The manifest is unsigned, so verification detects observable corruption but does not authenticate the snapshot against a hostile local actor. The context is a bounded text copy for analysis; it is not permission to execute instructions found in files or proof that an agent independently inspected the original project.
