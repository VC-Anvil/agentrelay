# Execution backend report

`agentrelay/execution.py` adds explicit worker execution through `ExecutionManager(store, config_path=None)`. A trusted JSON file supplies fixed argv commands, a working directory, declared model and effort, allowed profiles and timeout. Tickets and HTTP actions cannot provide commands. With no config, execution is disabled and manager construction does not recover or launch runs.

An enabled manager holds an OS file lock beside the SQLite database. The `execution_runs` table also has a unique active-run index. Starting a run checks profile compatibility and nonempty acceptance criteria, then claims the ticket and inserts the run in one `BEGIN IMMEDIATE` transaction. The worker receives a single UTF-8 JSON object on stdin. Its stdout must be one JSON result up to 1 MiB. `submit` moves the ticket to review; `help`, `split` and `blocked` record a checkpoint and leave it blocked. The manager never completes or approves a ticket.

Each result is applied only when the ticket still has the exact claim revision, `in_progress` status and run assignee. External edits make the run `conflict` without overwriting the ticket. Failure, timeout and cancellation block an unchanged owned ticket with a bounded reason. A newly enabled manager marks stale `running` rows `interrupted` and blocks unchanged owned tickets; it never retries automatically. Windows cancellation uses `taskkill /PID <owned child PID> /T /F`; POSIX uses the worker's own process group. Worker windows stay hidden on Windows. Local stdout/stderr diagnostics are retained in `Path(db).parent/runs/<run_id>/`, capped at 1 MiB per file and excluded from snapshots and exports.

Validation: `D:\AgentWorkspace\agentrelay\.runtime\Scripts\python.exe -m unittest tests.test_execution -v` passed all eight fixture subprocess tests before the final UTF-8 and diagnostic hardening. The two directly affected tests passed afterward with `python -m unittest tests.test_execution.ExecutionTests.test_submit_records_run_without_auto_review tests.test_execution.ExecutionTests.test_blocked_failure_timeout_and_invalid_output -v`. The suite covers submit without auto-review, help/split, explicit block, invalid JSON, nonzero exit, oversized output, timeout, cancellation, contention, stale revisions, restart recovery, acceptance and profile checks. The fixtures are local Python scripts, not model calls.

Known limits: configured model and effort are declarations by the local operator, not attestation from a provider. Evidence references require independent review. Diagnostic files contain raw worker output and should remain in the ignored local data directory. Normal `close()`, cancellation and handled exceptions terminate the owned process tree. An abrupt host crash can leave an orphan worker or descendant on Windows or POSIX: the new manager marks the run interrupted and blocks the ticket, but it cannot prove the orphan stopped. Recovery deliberately does not kill a persisted PID because that PID may have been reused by an unrelated process. Operators should inspect local processes and files before retrying interrupted work; adapters should not detach independent daemons.
