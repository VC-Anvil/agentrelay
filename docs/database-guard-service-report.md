# Guard for existing SQLite paths

`Store(path)` now distinguishes a new path from an existing file before creating parent directories, opening SQLite for writing, switching to WAL, creating tables or seeding profiles. It expands `~`, uses `lstat` to distinguish a dangling symlink from an absent path, and connects to the same resolved path it recognized (or to the resolved absolute path chosen for a new database). A new path bootstraps normally. An existing path is accepted only when a read-only SQLite connection recognizes the same five base tables and required columns previously used by `workspaces.require_agentrelay_database`. Recognized legacy databases still receive normal migrations, including missing plan and claim receipt tables. Foreign, corrupt, empty, incomplete, directory and dangling-link paths raise `DomainError` without acquiring a write connection to the candidate.

The base recognition and column map live in `agentrelay/database.py`; `workspaces.require_agentrelay_database` remains a DomainError wrapper, and `workspaces.BASE_SCHEMA_COLUMNS` remains an alias for callers. This keeps the recognition shared without a `Store` ↔ `workspaces` import cycle. Valid links to a recognized database remain supported where the host permits them. The check is a startup guard against mistaken paths, not protection against a process that substitutes files concurrently or against a foreign database deliberately imitating the base schema.

`tests/test_store_database_guard.py` checks new bootstrap and existing valid reuse, foreign sentinel content, corrupt bytes, zero bytes, valid empty SQLite, incomplete tables, all required tables with one missing column, views named like base tables, directories, legacy migration and links. A simulated HOME with a literal `~` decoy verifies that inspection and connection target the same file, including creation at a new expanded path. Rejected regular files are compared byte-for-byte and by `sqlite_master`; no WAL/SHM companions appear.
