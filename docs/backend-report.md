# Backend implementation report

`agentrelay/store.py` implements the v0.1 SQLite domain API with standard-library dependencies only. Each operation opens its own connection. Mutations use `BEGIN IMMEDIATE`; SQLite foreign keys and WAL are enabled. Ticket mutations use `expected_revision` for optimistic conflict detection, and each committed action creates a timestamped audit event. State and export reads use a single read transaction.

The readiness graph has two edge types: a ticket waits for each dependency, and a parent waits for each child. A DFS rejects any cycle, including one formed by a child depending on its parent. Dependencies require `done`; children can be `done` or `cancelled`. Manual `blocked` status remains until an explicit transition, including after a help child completes.

Profiles are recommendations. Astra's coordinator role, `gpt-6-astra` model and `high` effort are locked against edits; a claim for its profile also rejects conflicting supplied actual model or effort. Actual model and effort are recorded only when supplied on claim. Tickets in progress, review, or blocked with an assignee retain owner guards against other agents. Create and update events store values for scope history. Split children inherit priority and profile by default; their acceptance criteria remain child-specific. `seed_demo()` is explicit, idempotent and requires an empty ticket database; its eight Spanish tickets and `demo://` references are marked fictitious. No model execution, evidence verification or usage measurement is implied.

Validation: `D:\AgentWorkspace\agentrelay\.runtime\Scripts\python.exe -m unittest tests.test_store -v` passes the first 12 store tests. A thirteenth targeted test passes after a final rule for unassigned blocked tickets: only `human` may resume them. Cases cover persistence, two independent Store instances and stale revisions, dependency and mixed hierarchy deadlocks, ownership including paused work, Astra claim lock, audit values, lifecycle submission and independent review, acceptance criteria, parent readiness, help resume, split history, profile lock and demo isolation. Full HTTP/MCP and UI integration is owned by the root integrator.

Known limits: reviewers still make the substantive judgment; matching acceptance strings and evidence references only record their decision. The demo contains illustrative completed and review states, not a real execution record. SQLite transactions serialize mutations within one DB file; they do not coordinate external agents or launch model processes.
