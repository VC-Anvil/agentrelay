# AR-0021 · Propuestas de workers consultables por run

Antes del cambio, el conflicto reproducido en `.agentrelay/conflict-result-repro.json` dejaba intacta la edición humana, pero no exponía la propuesta en las consultas del run: éste quedaba `conflict` con `summary` vacío y la salida sólo seguía en `stdout.json` local. `execution_runs.result_json` ahora conserva la salida normalizada por `_validate_result` en una transacción separada, antes de `_apply_result`, sólo si el run todavía está `running`. La migración añade la columna nullable a tablas antiguas. El límite original de 1 MiB para stdout sigue vigente; el JSON ASCII normalizado admite hasta 4 MiB para no rechazar texto UTF-8 válido al escaparlo. Si supera ese límite, se rechaza sin truncar.

`get_run_result(store, run_id)` lee en una transacción un run concreto, su resultado `dict|null` y el estado actual `{id,revision,status,assignee}` del ticket. Incluye `claim_revision` y actor para comparar revisiones; no instancia `ExecutionManager`, no lee logs y acepta una tabla anterior sin `result_json` devolviendo `null`. Valida ID y rechaza resultados almacenados que no sean un objeto JSON finito dentro del límite. Snapshot, contexto, exportación e historial masivo siguen usando campos públicos sin propuesta. El backup SQLite sí conserva la columna y su valor.

`tests/test_run_results.py` usa workers Python locales de fixture, nunca un proveedor de modelos. Comprueba conflicto con edición concurrente intacta y propuesta retenida; submit y backup; rechazo de Store que retrocede checkpoint e hijos pero bloquea el ticket propio y conserva la propuesta; cancelación antes y después de captura (gate determinista antes de aplicar); salida excesiva; UTF-8 dentro de 1 MiB cuya forma ASCII supera 2 MiB; lectura legacy sin manager y migración. El servicio no reaplica propuestas.

Resultado propio: 7/7 pruebas nuevas y 8/8 pruebas existentes de `test_execution.py` pasan con `.runtime/Scripts/python.exe`; `git diff --check` pasa. En este sandbox dirigí `TEMP`/`TMP` sólo para las pruebas a `.agentrelay` porque SQLite no podía abrir el TEMP de Windows. La comprobación de un protocolo estructurado no verifica el contenido, los enlaces de evidencia ni que el proveedor haya ejecutado el modelo declarado. Cancelación o caída antes de la captura dejan `result=null`; un run antiguo sin propuesta también. El campo `model` del run procede de configuración, no de atestación del host; el modelo/esfuerzo efectivos de este paquete figuran como `unknown` en AR-0021.
