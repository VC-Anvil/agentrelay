# AR-0019 · Comando `overview`

El CLI admite `overview --workspaces PATH [--limit N]` y llama a `project_overview` antes de resolver o crear la base predeterminada. El registro es obligatorio; `--db` y `--workers` no son opciones de este comando. El servicio valida `N` en 1..20 (valor predeterminado 5). Sólo se imprime JSON UTF-8 después de una lectura satisfactoria; errores de dominio, sistema de archivos y SQLite producen diagnóstico sin traceback ni salida parcial.

`tests/test_cli_overview.py` ejecuta el comando en subprocess desde una carpeta aislada. Dos bases contienen ambas `AR-0001` con títulos distintos; la respuesta mantiene proyectos separados, versión, proyecto predeterminado, `urgent_open` entero y muestras acotadas de `ready`, `review` y `blocked`. Un `workers` configurado pero inexistente no se abre durante la consulta. También se prueban registro ausente, límites inválidos, opciones de ejecución no aceptadas y una segunda base corrupta: ninguna ruta de error crea `.agentrelay` o emite JSON parcial.

Resultado propio: las 3 pruebas nuevas y las 5 de `test_cli_readonly.py` pasan; `git diff --check` pasa. En `test_cli.py`, 4/5 pasan y la prueba de snapshot falla por `WinError 5` al leer `source` dentro del TEMP redirigido a `.agentrelay` en este sandbox. Esa ruta pertenece a snapshots, no al nuevo comando; no cambié fuentes ajenas ni elevé permisos. El TEMP predeterminado de Windows había negado SQLite en esta sesión, por lo que dirigí `TEMP`/`TMP` sólo durante las pruebas a `.agentrelay`. La validación integrada en entorno normal corresponde a Astra.
