# AR-0023 · Descubrimiento paginado de ejecuciones

La reproducción `.agentrelay/run-discovery-repro.json` muestra un ticket con dos runs existentes cuyos IDs no podían obtenerse mediante una consulta estructurada. `list_runs(store, *, ticket_id=None, status=None, limit=20, before_id=None)` devuelve metadatos por run y `has_result`; no carga `result_json`, logs ni `ExecutionManager`. Un resumen de run contiene exactamente los campos públicos de `run_results.py` más ese booleano. El cuerpo de la propuesta sigue disponible sólo con `get_run_result` para un ID elegido.

La lectura usa una transacción SQLite. Filtra por ticket y/o estado, calcula `total` antes del cursor y pagina por `(started_at DESC, id DESC)` con `before_id` exclusivo. El run ancla debe existir, pero puede haber cambiado de estado desde la página anterior; su fecha e ID permiten continuar el orden sin exigir que aún coincida con el filtro. Una inserción más nueva no vuelve a aparecer en páginas antiguas. `next_before_id` se entrega sólo cuando hay una fila adicional. El límite estricto es 1..100. Ticket desconocido y cursor desconocido dan 404; un cursor de otro ticket con filtro da 400. Sin tabla de ejecuciones, una consulta válida devuelve página vacía; la lectura de una tabla anterior a `result_json` informa `has_result=false` sin migrarla.

`tests/test_run_history.py` cubre 125 runs con empates de fecha, inserción entre páginas, totales y fin de paginación; filtros de ticket y estado; cambio de estado del ancla; esquema ausente y legacy sin mutaciones; y tipos, límites y cursores inválidos. Los datos se preparan en un fixture SQLite aislado; no hay proveedor de modelos ni inferencia.

Resultado propio: 4/4 pruebas nuevas pasan con `.runtime/Scripts/python.exe`, con `TEMP`/`TMP` dirigidos sólo para la prueba a `.agentrelay` porque el sandbox negó SQLite en el TEMP de Windows. Esta API acota el número de runs por página, no el tamaño de campos como `summary` o `error`, ni acredita ahorro de SQL o tokens. El campo `model` sigue siendo una declaración de configuración, no una atestación del proveedor; AR-0023 registra modelo/esfuerzo efectivos `unknown`.
